# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm install            # once; tooling only — nothing from node_modules ships to the browser
npm run dev            # Tailwind CLI watcher → assets/css/main.css
npm run serve          # static dev server with gzip at http://localhost:5173/  (fetch() is blocked over file://); PORT=… or `node scripts/serve.mjs <port>` to change
npm run check          # validate data/*.json — exits 1 on any schema/reference/price/image error
npm run build          # minified CSS → assets/css/main.css  ← this file is COMMITTED; Pages has no build step
npm run e2e            # 37-assertion puppeteer suite; requires `npm run serve` running; screenshots → .e2e/
npm run placeholders   # regenerate SVG placeholder art from the data; never overwrites a non-.svg file
```

Before every push: `npm run check && npm run build && npm run e2e`. There is no CI (planned for M5).

`e2e` is a single script, not a test runner — there is no per-test filter. To check one thing, edit `scripts/e2e.mjs` or run a one-off puppeteer snippet against the same server. Env overrides: `E2E_URL`, `CHROME_PATH` (defaults to the standard Chrome install path). Lighthouse: `CHROME_PATH=... npx lighthouse@latest http://localhost:5173/ --form-factor=mobile --screenEmulation.mobile --output=json --output-path=<file>` — the launcher throws on exit on this machine but the report is written.

Planning docs (`plan.md`, `track.md`, `project_context.md`) live **one level up**, outside the repo. Update `../track.md` after each milestone step.

This directory is its own git repo (no remote yet) nested inside the parent `Shohure` repo, which does have a GitHub remote. Commit here; never `git add` this folder from the parent — see the "Two git repositories" section in `../CLAUDE.md` for the pending layout decision.

## Architecture

The store brand is **Shohure — শহুরে** (Bengali for "urban"), positioned as *the South Asian pantry for city life*. Copy follows that: short, confident, city-minded (small-kitchen pack sizes, delivery to any floor, same-day inside the Berlin S-Bahn ring); no "authentic/traditional/village" framing. The design follows it too: neutral concrete-toned off-white (`cream`) rather than a warm cream, crisp `radius-card`, and hero banners generated by `scripts/placeholders.mjs` with a low-contrast skyline. Written out in one line (titles, metadata, docs, copyright) it is always `Shohure — শহুরে` with an em-dash; the wordmark stacks it as Latin "Shohure" in Poppins with a small `lang="bn"` শহুরে beneath it; Bengali glyphs come from the OS fallback font (no Bengali webfont is shipped). The mark is an "S" monogram on a rounded square, inline in the header/footer and in `assets/img/favicon.svg`.

Static site: one hand-written HTML page per route, Tailwind v4 via CLI, vanilla ES modules, JSON data. Everything below the fold is rendered client-side from `data/*.json` — this is a deliberate M1 trade-off (SEO cost accepted) and the trigger for moving to a static-site generator at M5 (>~20 products).

**Boot sequence (`assets/js/main.js`):** static parts start immediately (announcement bar, hero carousel, skeletons into every `[data-product-row]`); then `loadData()` resolves and, in order, nav → catalogue → product rows + scroll-row arrows → brand strip → cart UI → search. If the JSON fetch fails, rows show a "run `npm run serve`" message.

**Data layer (`data.js`):** fetches the three JSON files once and returns lookup helpers (`topLevel()`, `children(slug)`, `tiles()`, `bySubcategory(slug)`, `productBySku` / `productBySlug` Maps, `brand()`, `category()`). All rendering code takes this `data` object; nothing re-fetches.

**Rendering (`render.js`):** `productCard(p, data)` is the most reused component in the project — M2/M3 must reuse it unchanged (fix the shared component if it needs changes). `skeletonCard()` mirrors it tag-for-tag with transparent text so heights match exactly. `html()` escapes everything interpolated into markup.

**Cart (`cart.js`):** `localStorage` key `cart:v1`; `write()` dispatches a `cart:changed` event that the badge and drawer subscribe to — that event is the only way UI learns about cart changes. `reconcile(data)` runs on load and drops vanished SKUs / updates changed prices / flags sold-out items. `render()` re-creates the line list with `innerHTML`, so it captures and restores focus on the active stepper — keep that when touching it.

**Drawers (`drawer.js`):** one shared implementation for the mobile nav and the cart: backdrop, `body[data-lock]`, Escape, Tab focus trap, focus restore to the trigger with `aria-expanded` sync. Any new slide-over must use `openDrawer(el, trigger)` rather than roll its own.

**Nav (`nav.js`):** desktop mega-menu panels and the mobile accordion drawer are both generated from `categories.json` (`parent: null` = top level). Hover has open/close delays; focus opens; Escape closes and returns focus.

**Carousels (`carousel.js`):** `initHero` (fade, autoplay paused on hover/focus/hidden tab, disabled under `prefers-reduced-motion`, swipe, ← →) and `initScrollRow` (CSS scroll-snap rows; arrows disable at the ends via Resize/MutationObserver and are not rendered on `(hover: none), (pointer: coarse)`).

**Styling (`src/input.css`):** all tokens are in `@theme` (Tailwind v4 — no `tailwind.config.js`); hand-written pieces are in `@layer components`. Tailwind v4 cannot `@apply` a custom component class inside another — variants are separate classes composed in markup (`class="btn btn-primary"`, `class="badge badge-sale"`). Fonts are self-hosted `woff2` (no Google Fonts — GDPR); add a weight by copying the file from `@fontsource` and adding an `@font-face`.

## Rules that are load-bearing

- **Relative links only** (`category.html?slug=…`, `assets/…`). The site must work at `/`, `/shop/`, and a custom domain. Canonical/OG URLs in `index.html` are the only absolute ones.
- **Prices are integer cents.** Unit price (`3,00 € / kg`) is derived in `format.js`, never stored. `npm run check` enforces this and every cross-reference.
- **Every `localStorage` access is inside `try/catch`** — Safari Private Mode throws and an unhandled throw kills every script after it.
- **Every container JS fills must reserve its final height in the HTML** (skeleton tiles, `min-h-*`). An empty `<ul>` growing on render was the entire CLS (0.134 → 0). Adding a new JS-rendered section without a placeholder will regress this.
- **Every `<img>` has `width`/`height`**; below the fold is `loading="lazy"`; the first catalogue tile is `eager` + `fetchpriority="high"` because it is the LCP element on phones (the gradient hero SVG is too low-entropy for Chrome to count).
- **Accessible names must contain the visible text** (Lighthouse `label-content-name-mismatch`), and controls whose text is hidden on some breakpoint need an `aria-label` (the Basket button).
- Palette tokens were darkened to pass AA (`brand-600 #b05a04`, `ink-faint #6f6a64`); check contrast before changing them.
- Brands, products and imagery are **fictional placeholders** — never add scraped Desigros images or real brand logos. The payment marks are deliberately generic text, not card logos.
- No secrets in this repo, ever — every deployed file is public. Commerce (M6) uses publishable keys via a hosted provider.
